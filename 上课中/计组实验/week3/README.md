# 单周期 CPU 扩展说明：`andi` 与 `bne`

## 本次改动概览

在现有单周期 CPU 的基础上，新增两条 RV32I 指令：

- `andi`
- `bne`

这两条指令分别代表：

- 一条 I-type 的按位与立即数指令
- 一条 B-type 的不等分支指令

从数据通路角度看，这次工作并不是新增一条完整的新执行路径，而是在现有单周期 CPU 的框架上，把已有的立即数扩展、ALU 运算、分支跳转这些通路重新组织起来，让它们可以正确支持这两条新指令。

因此，本次改动主要集中在以下几个文件：

- `ctrl.v`：增加 `andi` / `bne` 的译码与控制信号生成
- `alu.v`：增加 `bne` 的条件判断方式
- `rv32_sc_sim.dat`：把测试样例直接并入默认测试程序
- `sccomp_tb.v`：把默认 testbench 改成自动检查 `andi` / `bne` 的执行结果
- `Makefile`：延长默认仿真时间，保证默认样例能完整跑完

## 两条新指令的理论介绍

### `andi`

`andi` 是一条 I-type 指令，语义为：

```text
rd = rs1 & sext(imm[11:0])
```

它的几个关键点是：

- 操作数一来自寄存器 `rs1`
- 操作数二来自 12 位立即数
- 这个立即数在 RV32I 中要先做符号扩展，再参与按位与运算
- 结果写回寄存器 `rd`

对应编码特征为：

- opcode：`0010011`
- funct3：`111`

### `bne`

`bne` 是一条 B-type 指令，语义为：

```text
if (rs1 != rs2)
    PC = PC + offset
else
    PC = PC + 4
```

它的几个关键点是：

- 读取两个寄存器 `rs1` 和 `rs2`
- 比较两者是否不相等
- 若不相等，则跳转到 `PC + B-type immediate`
- 若相等，则顺序执行下一条指令

对应编码特征为：

- opcode：`1100011`
- funct3：`001`

## 放到现有单周期数据通路里的理解

### `andi`

对单周期 CPU 来说，执行 `andi` 需要以下几个操作：

1. 从指令中识别出它是 `andi`
2. 从寄存器堆读出 `rs1`
3. 把 12 位立即数扩展成 32 位
4. 让 ALU 做按位与
5. 把 ALU 结果写回 `rd`

### `bne`

执行 `bne` 则是需要以下几个操作：

1. 从指令中识别出它是 `bne`
2. 从寄存器堆读出 `rs1` 和 `rs2`
3. 判断两者是否不相等
4. 若条件成立，令 `NPC = PC + branch_offset`
5. 若条件不成立，令 `NPC = PC + 4`

## 具体代码改动说明

### `ctrl.v`：新增指令译码

#### `andi` 的译码

在 `ctrl.v` 中，本来已经有 I-type 算术指令的总类判断：

```verilog
wire itype_r = ... // 0010011
```

这次增加了：

```verilog
wire i_andi = itype_r & Funct3[2] & Funct3[1] & Funct3[0];
```

这表示：

- 先满足 opcode 是 `0010011`
- 再满足 `funct3 = 111`
- 就把它识别为 `andi`

这里的设计思路是“先做大类判断，再做子类细分”，和现有 `addi`、`and`、`or` 等指令的译码风格保持一致。

#### `bne` 的译码

同样地，原代码已经有 B-type 的总类判断：

```verilog
wire sbtype = ... // 1100011
```

这次增加了：

```verilog
wire i_bne = sbtype & ~Funct3[2] & ~Funct3[1] & Funct3[0];
```

这表示：

- opcode 是 `1100011`
- `funct3 = 001`
- 则识别为 `bne`

而已有的 `beq` 则是 `funct3 = 000`，两条指令由此被区分开。

### `ctrl.v`：为 `andi` 接通立即数与 ALU 控制

#### I-type 立即数扩展

原工程中，`EXTOp[4]` 主要用来选择 I-type 立即数扩展。为了让 `andi` 和 `addi` 一样走 I-type 立即数通路，这次把：

```verilog
assign EXTOp[4] = i_addi | itype_l;
```

改成了：

```verilog
assign EXTOp[4] = i_addi | i_andi | itype_l;
```

这样 `andi` 的 12 位立即数也会进入 `EXT.v` 做 I-type 扩展。值得注意的是：`andi` 的立即数是符号扩展，不是零扩展。

#### ALU 控制码映射

`andi` 最终要让 ALU 执行按位与，因此在 `ALUOp` 的组合逻辑中，需要让 `i_andi` 生成与 `and` 相同的 ALU 控制码。

### `ctrl.v`：为 `bne` 接通分支控制

#### 分支条件接入 NPC 控制

原来控制器对分支跳转的处理，实质上是：

- 如果是 `beq`
- 且比较条件成立
- 就让 `NPCOp` 选择分支地址

为了支持 `bne`，本次把 `NPCOp[0]` 的生成逻辑改成：

```verilog
assign NPCOp[0] = (i_beq | i_bne) & Zero;
```

这里的含义是：

- 只要当前指令是 `beq` 或 `bne`
- 并且 ALU 送来的条件标志为真
- 就执行分支跳转

注意这里的 `Zero`，在本次修改后已经不再被单纯理解为“ALU 结果等于 0”，而是更准确地被当作“分支条件成立标志”。

对于：

- `beq`：`Zero = 1` 表示相等，应该跳转
- `bne`：`Zero = 1` 表示不等，应该跳转

这也是为什么 `NPC.v` 本身不需要改动。因为对 `NPC.v` 来说，它只需要知道“当前这一拍要不要跳”，并不需要关心具体是 `beq` 还是 `bne`。

`bne` 不能直接复用 `beq` 的 ALU 控制码，否则控制器虽然知道它是分支指令，但 ALU 无法区分当前到底应该把“相等”还是“不等”当作条件成立。

因此，本次让 `i_bne` 生成一个单独的控制码：

- `ALUOp_bne = 5'b00101`

在 `ctrl.v` 中，它是通过给 `ALUOp[2]` 和 `ALUOp[0]` 加入 `i_bne` 来实现的。

#### `bne` 的 ALU 控制码

这里补充说明一下为什么 `bne` 需要单独的 ALU 控制码。

如果直接让 `bne` 和 `beq` 共用同一个 ALU 控制码，那么控制器虽然能识别出当前是分支指令，但 ALU 无法进一步区分：

- 当前应该判断“是否相等”
- 还是应该判断“是否不等”

因此，本次专门保留了 `ALUOp_bne = 5'b00101`，让 `alu.v` 可以在 `Zero` 的生成逻辑中识别出当前是在执行 `bne`。

### `alu.v`：新增 `bne` 的条件判断

在 `alu.v` 中，本次做了两件事。

#### 增加 `ALUOp_bne` 的 case

首先，在 `case(ALUOp)` 中增加了：

```verilog
`ALUOp_bne: C = A - B;
```

也就是说，`bne` 在运算本身上仍然使用减法比较。这和 `beq` 的实现思路一致，因为比较相等/不等，本质上都可以通过 `A - B` 来辅助判断。

#### 修改 `Zero` 的定义

真正关键的改动在这里：

```verilog
assign Zero = (ALUOp == `ALUOp_bne) ? (A != B) : (C == 32'b0);
```

原来的 `Zero` 可以理解为：

- `C == 0` 时为真

这个定义适合 `beq`，因为：

- `A - B == 0` 等价于 `A == B`

但它不适合 `bne`，因为 `bne` 需要的是：

- `A != B` 时条件成立

因此本次改成了条件化定义：

- 如果当前是 `bne`，那么 `Zero = (A != B)`
- 否则仍然保持原来的 `Zero = (C == 0)`

这样一来：

- `beq` 仍然通过“减法结果是否为 0”来判断
- `bne` 则通过“两个寄存器是否不等”来判断

于是控制器虽然只接收一个 `Zero` 输入，但已经可以同时支持：

- 相等分支
- 不等分支

## 默认测试样例的修改

为了对新增的指令进行验证，本次把测试样例直接并入了默认程序 `rv32_sc_sim.dat`，也就是说现在执行：

```bash
make run
```

默认流程就会覆盖 `andi` 和 `bne`。

### 加入到默认程序末尾的测试片段

追加到程序末尾的几条指令可以理解成下面这段汇编：

```asm
andi x21, x5, -1
bne  x21, x5, skip1
addi x22, x0, 1
bne  x21, x6, skip2
addi x23, x0, 1
addi x24, x0, 2
jal  x0, 0
```

它对应的测试意图是：

- `andi x21, x5, -1`
  - 用来验证 `andi` 是否正确走了 I-type 符号扩展
  - 因为 `-1` 扩展后应为 `0xffffffff`
  - 所以结果应满足 `x21 = x5`
- 第一条 `bne x21, x5, ...`
  - 因为两者相等，所以不应跳转
  - 紧跟着的 `addi x22, x0, 1` 必须执行
- 第二条 `bne x21, x6, ...`
  - 因为 `x21 != x6`，所以应跳转
  - 中间的 `addi x23, x0, 1` 必须被跳过
  - 最终 `addi x24, x0, 2` 应执行

### 预期结果

如果实现正确，程序执行到测试末尾时应满足：

- `x21 = 32'h12345000`
- `x22 = 32'h00000001`
- `x23 = 32'h00000000`
- `x24 = 32'h00000002`

其中：

- `x21` 用来验证 `andi`
- `x22` 用来验证第一条 `bne` 的 not-taken 路径
- `x23` 用来验证第二条 `bne` 的 taken 路径确实跳过了某条写回
- `x24` 用来验证分支目标指令确实被执行
